二、可修改意见（按投入产出分组）

A 组 · 高价值 · 低成本

1. 标签页点击即筛选

对标：Calibre / Kavita「点标签即检索」工作量：小

详情页 / 卡片上的标签目前只是展示。索引页已支持 ?tag=xxx 参数，只需把标签 span 改成指向 /？tag=标签名 的链接即可，复用现有筛选逻辑，零后端改动。

2. 自动备份 library.json

对标：所有成熟方案都有备份工作量：小

写回数据前自动 cp 一份带日期的 data/library.json.bak.YYYYMMDD，保留最近 7 份、超限滚动删除。防手误/损坏，且你跨电脑迁移时更安心。

3. 封面自动抓取（复用豆瓣通道）

对标：BookLore / Kavita 元数据自动带封面工作量：小–中

详情页已有「按书名取简介」的豆瓣通道，顺手把封面图也抓下来存到 static/covers/。缺封面的书（约占一部分）自动补图，封面墙观感立刻提升。仍遵守「不碰原文件」约定（图存到程序目录）。

4. 统计仪表盘

对标：BookLore reading stats工作量：中

新增 /stats：藏书总量、状态分布（未读/在读/已读/搁置）、阅读进度分布、星级分布、标签 Top10、作者 Top10、按出版年趋势。侧栏加入口。纯读 library.json，无写入风险。

B 组 · 高价值 · 需投入

5. 在线阅读器（EPUB / PDF）

对标：BookLore / Calibre-Web 内置阅读器｜ 工作量：大（前端为主）

这是与主流程序最大的体验差距——你现在只有「下载后本地打开」。可嵌入 epub.js + PDF.js 实现浏览器内阅读，支持翻页/字号/主题。只读不写，符合你的硬性约定。建议作为下一个大版本的核心。

6. 智能书架 / 收藏夹

对标：BookLore Magic Shelves / Kavita Smart Collections工作量：中–大

用户可自建命名书架（如「2026 待读」「科幻经典」），拖书入架；或按规则（标签/星级/状态）自动归集。把侧栏占位的两个入口真正用起来。

7. 阅读进度记录

对标：全系均有工作量：中

在 book 加 progress 字段，详情页可标记「读到第 X% / 已读 N 页」。配合在线阅读器体验最佳；单独做也能用。

8. 发送到设备 / 邮件

对标：Calibre-Web Send-to-Kindle工作量：中

若你有 Kindle 或固定邮箱，可加「📤 发送」按钮调用 SMTP 把文件发到设备。需要你提供邮箱/授权码，涉及外部凭证。

C 组 · 可选增强

9. OPDS 目录

对标：全系支持工作量：中

暴露 /opds 让 Moon+ Reader / KOReader 等手机 App 直接连你的库浏览+下载。适合「手机读、电脑管」的场景。

需常驻服务可外网/局域网访问

10. 多用户 / 权限

对标：BookLore / Calibre-Web工作量：大（安全）

家庭共享时才有意义。对当前「单机个人使用」属过度工程，优先级放低。

11. 移动端深度适配 + 12. 多格式文件登记

对标：Kavita / Calibre工作量：中

移动端现有响应式基础可再打磨；多格式需把「单文件路径」模型放宽为「一书多格式」，下载时可选格式。二者都非紧急。

约束提醒：你的硬性约定是「删除/导入绝不修改磁盘上的电子书文件，只动元数据」。 因此 格式转换（需重写文件） 与你的约定冲突，不建议做；而在线阅读器、封面抓取、进度、统计、书架、备份均为「只读/只写程序目录」， 与约定兼容，可放心推进。另外你是单机个人使用，多用户 / OPDS 的优先级可明显低于 A、B 组。
建议落地顺序（ROI 视角）：
  1. A1 标签点击筛选 → A2 自动备份 → A3 封面抓取（三者改动小、当天可上线）
  2. A4 统计仪表盘（一次性读数据，性价比高）
  3. B5 在线阅读器（体验质变，但工期最大，建议单独排期）
  4. B6 智能书架 / B7 阅读进度 → 按需
  5. C 组（OPDS / 多用户 / 多格式）按真实需求再定
